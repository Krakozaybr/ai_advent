# Демонстрационные доски AI Advent, дни 1–30

Это внешний учебный seed-пакет. Платформа v3 не знает о челлендже. JSON доски
лежат в `boards/`; импорт использует общий `POST /api/boards/import`, который
повторно находит доску по `externalId` и не перезаписывает её. Bootstrap
настраивает отсутствующие демонстрационные записи через обычные API. Он
сохраняет существующие факты, память, задачи и выбор MCP-инструментов.

## Подготовка

Собери JSON и подготовь реестр MCP **до запуска backend**:

```sh
node examples/ai-advent/build-seed-pack.mjs
node examples/ai-advent/prepare-mcp-registry.mjs
```

Скрипт реестра создаёт `v3/data/mcp-servers.json` только если файла ещё нет.
Если там уже есть настройки, скрипт оставляет файл без изменений. Проверь, что
в имеющемся реестре доступны `local-catalog` и `ai-advent-demo`, иначе дни 16–17
не смогут подключить демонстрационный mock. Серверы `demo-events` и `demo-notes`
для дней 19–20 встроены в backend и не требуют редактировать реестр.

Запусти backend и frontend в отдельных терминалах:

```sh
cd v3/backend && ./gradlew run
```

```sh
cd v3/frontend && npm run dev
```

Затем импортируй доски и выполни bootstrap через v3 API:

```sh
node examples/ai-advent/import.mjs
node examples/ai-advent/bootstrap.mjs
```

По умолчанию используется `http://127.0.0.1:8787`; другой адрес задаётся
переменной `BOARD_API_URL`. `bootstrap.mjs` также повторно вызывает импорт для
дней 10–25: это безопасный способ получить ID досок и сверить текущее состояние.
Повторный запуск не меняет уже существующие значения и задачи. Реальное
расписание для дня 18 seed и bootstrap не создают.

Чтобы импортировать одну доску без начальной настройки:

```sh
node examples/ai-advent/import.mjs board-05.json
```

## Сценарии показа и записи видео

В каждой доске пользовательские сообщения служат стартовыми запросами. Тексты
ответов с пометкой `Демонстрационный ответ` — заготовки, а не результат модели.
Перед записью можно очистить примерные ответы и запустить ленты через выбранного
провайдера. Для MCP выбери указанную модель OpenRouter. Изменяющие инструменты
попросит подтвердить интерфейс; подтверждай запись только после просмотра.

| День | Что показать |
|---|---|
| 1 | На доске «Первый запрос» отправь простой запрос через Codex, вошедший по подписке ChatGPT. Покажи первый ответ и сохранённую историю. |
| 2 | Сравни соседние ленты: свободный ответ и заданные строки/длина/stop. В обеих используй один и тот же запрос из истории. |
| 3 | Сравни прямой, пошаговый и экспертный подходы. В ленте «Улучшение запроса · два вызова» отправь стартовый запрос, дождись переписанной формулировки, затем скопируй её в новый запрос и попроси решить задачу. Это два реальных последовательных API-вызова. |
| 4 | Отправь одинаковую задачу через OpenRouter при temperature 0, 0.7 и 1.2. Сравни разнообразие формулировок; изменение ответа само по себе не доказывает качество. |
| 5 | Отправь дословно одинаковый запрос в трёх лентах с фиксированными `temperature=0.2` и `max_tokens=256`. Сравни ясность и полноту. Цена ниже — снимок карточек OpenRouter от 2026-09-27; фактическую стоимость показывай только при наличии её в ответе API. Qwen3 8B на карточке помечена к выводу 2026-10-09. |
| 6 | Через Codex обсуди задачу планировщика книжного клуба. Покажи сохранённую сущность агента и связь с лентой, а также эффективные инструкции агента, которые backend включает в запрос модели. |
| 7 | Продолжи разговор после перезапуска backend или обновления страницы. Покажи, что transcript сохранён. |
| 8 | Сравни короткую и длинную историю и раскрытый состав отправки. В третьей ленте бюджет 256 — локальная оценка/настройка приложения, а не доказанный предел контекстного окна модели и не обязательно отказ провайдера. Не называй этот пример реальным превышением лимита модели. |
| 9 | Сравни `full`, последние N и `summary_window`. Заготовленная сводка — демонстрационная. Покажи watermark и состав отправки: сводка заменяет сообщения до своей границы, а после неё передаются только новые сообщения. |
| 10 | В обеих соседних лентах прочитай Sticky Facts через `read_facts`. Попроси модель предложить `update_fact`; проверь pending approval и подтверди или отклони его. Сравни постоянный факт и ветвление от checkpoint. |
| 11 | В первой ленте `sliding_window` с N=1 оставляет старое сообщение в transcript, но выводит его из отправляемого окна. Через `history_search`/`history_get` найди срок хранения. Во второй ленте прочитай working и longTerm через `board-memory`, затем запроси `memory_propose_write` и покажи approval до записи. |
| 12 | Отправь одинаковый запрос двум лентам. Покажи тексты AGENTS в настройках лент и сравни стиль ответа. Отдельного профиля в данных нет. |
| 13 | Прочитай задачу инструментами `board-tasks`, предложи изменение через MCP, подтверди его в UI и снова прочитай задачу. Покажи одинаковое сохранённое состояние в панели задач. |
| 14 | Покажи AGENTS-инструкции с правилами. Попроси план и вручную отметь, где модель соблюла или нарушила каждое правило. Это prompt-level влияние, а не жёсткая проверка приложения. |
| 15 | Через `board-tasks` предложи утверждение плана и дождись approval. После утверждения вручную продвигай состояние по одному этапу через UI; покажи шаг, ожидаемое действие и паузу. |
| 16 | Открой панель каталога подключений и покажи состояние `ai-advent-demo`, инструмент `lookup_demo_event` и схему аргумента. На этом шаге модель не вызывай. |
| 17 | Отправь запрос на `lookup_demo_event` с ID `spring-book-swap`. Покажи реальный MCP tool call, аргумент и структурированный ответ. Это безопасный статический mock: он не ходит в сеть и ничего не меняет. |
| 18 | Создай одноразовое расписание в панели доски: по таймеру задание отправится агенту, который вызовет подключённый `lookup_demo_event`. Покажи запись запуска в истории и ответ в ленте. Перед показом повтори bootstrap, чтобы подключить инструмент к уже созданной доске. |
| 19 | На отдельном экране введи «обмен книгами» и запусти фиксированную цепочку `search_events → summarize_events → save_summary`. Покажи аргументы и результат каждого шага, включая путь сохранённого файла. Модель здесь не выбирает инструменты. |
| 20 | В настройках ленты покажи два MCP-сервера и три разрешённых инструмента. Попроси агента найти событие, сделать сводку и сохранить её. Раскрой фактические вызовы, затем в настройках MCP проверь аргументы `save_summary` и подтверди запись. Здесь порядок вызовов выбирает модель. |
| 21 | Через учебный CLI построй два индекса и сравни попадание ожидаемых источников в top-4. |
| 22 | Сравни ответы без RAG и с RAG на 10 вопросах; результат сохраняется в локальный отчёт. |
| 23 | Сравни сырую выдачу и выдачу после порога и переоценки; в чате проверь переформулировку вопроса с контекстом задачи. |
| 24 | Проверь дословные цитаты и отказ с просьбой уточнить при слабом контексте. |
| 25 | В CLI-чате зафиксируй цель и ограничения; запусти два сценария по 12 ходов. |
| 26 | Покажи подключение к Ollama и три реальных запроса разной сложности. |
| 27 | На отдельном экране отправь вопрос локальной модели и покажи ответ без облачного ключа. |
| 28 | Построй локальные эмбеддинги прежнего корпуса; покажи веб-ответ с цитатами и отчёт повторных запросов. |
| 29 | Сравни параметры и шаблон RAG на одинаковых вопросах; покажи скорость, память и полноту ответов. |
| 30 | Запусти HTTPS-чат на домашнем ноутбуке; с другого компьютера проверь ключ, историю, параллельные запросы и ограничения. |

Подробная инструкция для дней 16–20 и план видеозаписи: [days-16-20-video-guide.md](days-16-20-video-guide.md).

Дни 21–25 выполняются через [учебный RAG CLI](rag-guide.md). Доски этих дней —
карточки-навигация: обычная лента v3 не подключена к индексу и не выдаёт RAG-ответ.

Дни 26–28 также имеют карточки-навигацию, но отвечают на отдельном веб-экране
через Ollama. [Подготовка и сценарий видео](local-llm-guide.md).
