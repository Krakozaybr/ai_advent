# Дни 29–30: оптимизация и приватный сервис

Команды запускаются из корня проекта. Новые дни не меняют настройки 26–28.
Код дня 30 должен быть перенесён на Windows-ноутбук; наличие кода на основном
компьютере не означает, что сервис уже развёрнут на втором.

<a id="day-29"></a>

## День 29 — настройка RAG по русской классике

Нужны запущенный Ollama и локальный индекс дня 28.

```sh
npm run --silent local -- optimize
npm run --silent local -- report 29 --details
```

Проверяются три прежних вопроса (гайки, адрес Ваньки, карты) по два раза.
Для полной проверки десяти вопросов: `npm run local -- optimize --all`.
Индекс и векторы вопросов одинаковы в обоих режимах. Модель прогревается
перед измерениями; время включает поиск по готовому вектору, генерацию,
контроль цитат и возможное исправление, но не подготовку векторов.
Время также включает опрос памяти, поэтому малые различия в миллисекундах
не стоит интерпретировать как доказанное ускорение.

| Параметр | До | Кандидат после |
| --- | --- | --- |
| temperature | 0 | 0.1 |
| Контекст, токены | 8192 | 6144 |
| Лимит JSON-ответа | 800 | 640 |
| Лимит обычного ответа | 4096 | 1024 |
| Шаблон | Прежний RAG | Полный ответ на каждую часть вопроса, без сокращения имён и перечислений |

Отчёт показывает настройки, ошибки, отказы, время и память загруженной
модели из `/api/ps` с опросом каждые 500 мс. Это не пик RSS процесса;
GPU-память на Mac — объединённая память, на Windows её устройство нужно
проверить отдельно. Метрики и исходные ответы находятся в
`v3/data/rag/classics-ollama/day29-optimization.json` и не коммитятся.
Попадание источника не означает правильный ответ. Сверяй ожидание с ответом
и цитатами; ухудшение полноты — причина не выбирать такой профиль.

На [экране дня 29](http://127.0.0.1:5173/?localDay=29) можно выбрать «До»
или «После» и отправить одинаковый вопрос. История между вопросами здесь
не используется. CLI выбранного профиля:

```sh
npm run --silent local -- rag-optimized "Как Ванька подписывает адрес на конверте письма дедушке?"
```

Модель `qwen3:4b` уже квантована в Q4_K_M. Вариант Q8_0 занимает около
4.4 GB, поэтому скачивается только отдельной командой:

```sh
npm run local:quantization
npm run --silent local -- optimize --quantization
npm run --silent local -- report 29 --details
```

Этот режим сравнивает оба профиля также на Q8_0. Не объявляй сравнение
квантования выполненным до окончания загрузки и настоящих запросов.
Для RTX 3050 начни с Q4_K_M; точный объём VRAM и загрузку проверь `nvidia-smi`.

Для видео без комментариев покажи команды сравнения и отчёт с подробностями,
параметры и ответы «до/после». Первое неудачное ускорение тоже можно показать:
меньшая память не оправдывает потерянную часть ответа.

Проверка на основном компьютере (macOS), 10 октября 2026: по три вопроса
с двумя повторами, обе конфигурации Q4_K_M. Исходный профиль отвечал в среднем
за 19.04 с и занимал 3678 MiB по `/api/ps`; новый — 19.11 с и 3386 MiB.
Памяти меньше примерно на 8%, ускорения в этом прогоне нет. Исходная модель
неверно перечисляла карты; новый шаблон правильно назвал тройку, семёрку,
туз и пиковую даму вместо туза, сохранил полный адрес Ваньки и цель отвинчивания
гаек. Это ручная проверка этих трёх вопросов, не оценка всей базы.
Q8_0 в этом прогоне не проверен: загрузка остановлена из-за низкой скорости.

## День 30 — Windows-ноутбук как сервер

На Windows нужны Node.js 22 или новее, копия кода проекта и Ollama.
Java, Gradle, Docker, веб-сервер разработки и ключ OpenRouter не нужны.
Для команды проверки нужны зависимости проекта: `npm ci`.
Ollama поддерживает RTX 3050; версия драйвера должна удовлетворять
[требованиям Windows](https://docs.ollama.com/windows).

Выйди из приложения Ollama в системном трее, чтобы не запустить два сервера.
В PowerShell, из каталога проекта, оставь этот терминал работающим:

```powershell
$env:OLLAMA_NO_CLOUD="1"
$env:OLLAMA_HOST="127.0.0.1:11434"
ollama serve
```

Во втором терминале:

```powershell
ollama pull qwen3:4b
ipconfig
```

Найди IPv4 Wi-Fi, например `192.168.1.20`. Ниже замени пример своим IP.

```powershell
npm run private -- setup 192.168.1.20
npm run --silent private -- token
npm run private -- serve
```

`setup` создаёт ключ и самоподписанный сертификат на полгода в
`data/private-service/`. На Windows каталог закрывается для других обычных
пользователей через ACL. Существующая конфигурация не перезаписывается.
Если создание сертификата требует повышения прав, выполни `setup` в PowerShell
от администратора под той же учётной записью. Сетевой порт автоматически
не открывается; Ollama остаётся на `127.0.0.1:11434`.

Переведи домашнюю Wi-Fi-сеть Windows в профиль «Частная». В PowerShell
от администратора разреши только порт приложения и домашнюю подсеть:

```powershell
New-NetFirewallRule -DisplayName "AI Advent private chat" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 3443 -LocalAddress 192.168.1.20 -RemoteAddress LocalSubnet -Profile Private -Program (Get-Command node).Source
```

Не открывай порт 11434 и не настраивай проброс портов роутера в интернет.
Ноутбук должен оставаться включённым, подключённым к питанию и не уходить
в сон во время проверки. Пока сервис работает в открытом терминале;
автозапуск при загрузке Windows не настраивается.

### Подключение с основного компьютера

Открой `https://192.168.1.20:3443`. Перед доверием к самоподписанному
сертификату сверь его SHA-256 с выводом `setup` на сервере. Разрешай только
этот конкретный сертификат; не отключай проверку TLS целиком.
Введи ключ в поле пароля и нажми «Проверить подключение».
Ключ и история находятся в памяти вкладки, а не в URL или localStorage.

Для автоматической проверки перенеси с Windows только **публичный**
`data/private-service/server.pem`, например в `data/windows-server.pem`
на основном компьютере. Приватные `.pfx`, `.key` и `config.json` не переноси.
Ключ передай отдельно по доверенному каналу и добавь в локальный `.env`:
`PRIVATE_SERVICE_TOKEN=твой_ключ`. Ни `.env`, ни ключ не показывай в видео.

```sh
npm run --silent private -- check https://192.168.1.20:3443 data/windows-server.pem
```

Проверка показывает HTTP 401 для неверного ключа, 413 для длинного контекста,
чат с запоминанием имени, два одновременных обращения, затем 429 при превышении
лимита. Правильность имени и арифметики проверь по напечатанным ответам:
HTTP 200 означает успешный вызов, а не доказанную правильность модели.
Запускай проверку после минуты без запросов, чтобы старый счётчик не мешал.
Если модель отвечает медленнее шести секунд и счётчик успевает сброситься,
проверка частоты может не достичь порога: это не доказательство его отсутствия.
Коды `rate_limited` и `queue_full` различают ограничение частоты и переполнение
очереди; оба возвращают 429.

Ограничения сервиса: 10 обращений к модели в минуту суммарно, один активный
запрос и один ожидающий, JSON до 16 KiB, вопрос до 1024 байт UTF-8, до четырёх
пар истории. Системный текст, история и вопрос вместе — до 2048 байт UTF-8;
это консервативное ограничение входа, не точный подсчёт токенов. Модель
использует контекст 4096 токенов и лимит ответа 1536. Диалог на сервере не
сохраняется, доступ к инструментам платформы и облачным моделям отсутствует.

Для видео: покажи сервис на Windows, чат на основном компьютере и команду
проверки с результатами. Настройку ключа сделай до записи. Пока нет настоящей
проверки между ноутбуками, день 30 нельзя считать развёрнутым и проверенным.
