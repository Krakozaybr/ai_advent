# Как показать дни 21–25 на видео

Индекс построен на 32 произведениях русской классики из Викитеки:
117 619 слов, около 294 страниц по 400 слов. Модель
`openai/text-embedding-3-small` преобразовала каждый фрагмент в 512 чисел.
По этим векторам поиск находит близкие по смыслу фрагменты.

Для ответов команда `npm run rag` использует `openai/gpt-4.1-mini`.
Модель можно заменить переменной `RAG_ANSWER_MODEL`, например
`RAG_ANSWER_MODEL=qwen/qwen3-30b-a3b-instruct-2507 npm run rag -- ask rag "вопрос"`.
Модель эмбеддингов от этого не меняется. Предыдущие результаты Qwen
сохранены отдельно в `evaluation-qwen.json` и `scenarios-report-qwen.json`:
в них часто встречались ошибки смысла и недословные цитаты.

Запись проводится в терминале. Доски v3 можно показать как оглавление,
но их обычные ленты пока не подключены к индексу. Работающий агент
для дней 21–25 — отдельная программа командной строки.

## Подготовка

Все команды запускай из корня проекта:

```sh
cd /Users/yarogrit/ai_advent
npm run rag -- summary
```

Увеличь шрифт терминала. Открой рядом
`v3/data/rag/classics/corpus/manifest.json` и этот сценарий.
Ключ читается из `.env`; сам файл и ключ на видео не показывай.

`summary`, `inspect`, `questions`, `report` не обращаются к модели.
`search` и `rewrite` вызывают сервис эмбеддингов; `ask`, `eval`,
`scenarios` и вопросы в `chat` дополнительно вызывают LLM.
`npm run rag` выбирает только публичную классику, без исходников проекта.
Корпус, индексы и результаты находятся в `v3/data/rag/classics/`, вне Git.

После клонирования репозитория готового индекса ещё нет. Выполни `npm ci`,
задай `OPENROUTER_API_KEY` в локальном `.env`, затем:

```sh
npm run rag:download
npm run rag -- index
npm run rag -- compare
npm run rag -- report
```

Это загрузит публичные произведения, построит оба индекса и создаст отчёт
сравнения. Ответы модели и длинные диалоги для дня 21 запускать не требуется.

## Что показали реальные проверки

Индекс и поиск готовы. Последний полный прогон с GPT-4.1 mini до уточнения
JSON-разметки входного контекста дал следующие результаты:

| Режим | Совпало с ожиданием по оценке модели | Ответов с источниками | Отказов |
| --- | ---: | ---: | ---: |
| Без RAG | 6 из 10 | 0 из 10 | 0 |
| Сырой RAG | 4 из 10 | 6 из 10 | 4 |
| RAG с фильтром | 5 из 10 | 6 из 10 | 4 |

В длинных сценариях источники были в 8 из 12 и 5 из 12 ответов. Поля цели
и ограничений сохранились, но в первом финальном ответе модель подменила
«Хамелеон» на «Злоумышленника», а во втором цитировала только «Шинель».
Поэтому день 25 пока нельзя считать полностью пройденным по качеству.
JSON-разметка метаданных после этого уточнена; отдельный вопрос по «Тоске»
прошёл проверку, но весь набор после этой последней правки ещё не повторён.

На видео можно показать работающий поиск, источники, перезапуск чата и
честное сравнение режимов. Утверждать, что RAG всегда улучшает ответ или
что длинный диалог всегда сохраняет цель по смыслу, пока нельзя.

## День 21 Индексация документов

Покажи манифест с произведениями и один исходный текст, например
`corpus/chekhov-vanka.md`. В манифесте есть автор, название, ссылка,
ревизия страницы и контрольная сумма. Парсер удаляет навигацию,
сноски и примечания, оставляет литературный текст.

```sh
npm run rag -- summary
npm run rag -- inspect fixed
npm run rag -- inspect structural
```

Покажи `source`, `title`, `author`, `section`, `chunk_id`, `text`,
`vectorDimensions` и начало вектора. Чанк — фрагмент произведения,
который индексируется и возвращается поиском отдельно.

| Стратегия | Разбиение | Фрагментов | Разделов |
| --- | --- | ---: | ---: |
| fixed | До 1100 символов, перекрытие около 140 символов | 772 | 32 |
| structural | Заголовки и главы, затем абзацы до 1500 символов | 641 | 78 |

Для демонстрации пайплайна повтори сборку и покажи сравнение:

```sh
npm run rag -- index
npm run rag -- report
```

Повторная сборка использует кеш оплаченных эмбеддингов.
На другом компьютере сначала выполни `npm run rag:download`,
затем `npm run rag -- index`: первая загрузка обращается к Викитеке,
первая индексация — к OpenRouter.

Что сказать: «Обе стратегии нашли нужное произведение в первой четвёрке
для 10 из 10 вопросов. Контрольные слова нужного эпизода попали в найденные
фрагменты в 7 из 10 случаев при фиксированном разбиении и в 9 из 10 при
структурном. Поэтому дальше использую структурный индекс».
Это результат поиска, не оценка качества ответа.

## День 22 Первый запрос с RAG

RAG означает, что перед ответом модель получает найденные фрагменты
произведений. Задай одинаковый вопрос в двух режимах:

```sh
npm run rag -- ask plain "Для чего Денис Григорьев отвинчивал гайки в рассказе «Злоумышленник»?"
npm run rag -- ask rag "Для чего Денис Григорьев отвинчивал гайки в рассказе «Злоумышленник»?"
```

В первом режиме нет поиска и проверенных источников. Во втором покажи
`answer`, `sources`, цитату про грузила и `chunk_id`.
Поля `beforeFilter` и `afterFilter` показывают путь найденного контекста.

Что сказать: «Модель без RAG может знать классику и ответить правильно.
Во втором режиме она получает конкретный текст, а приложение проверяет,
что цитата действительно взята из него». Не обещай улучшения точности,
которого не показало сравнение.

```sh
npm run rag -- questions
npm run rag -- report
```

В `classics-questions.mjs` — 10 вопросов, ожидания и нужные источники.
В `evaluation.json` — реальные ответы без RAG, с сырым поиском и с фильтром.
Для полного повторного прогона: `npm run rag -- eval`.
Оценку соответствия ожиданию делает отдельный запрос к модели;
спорные строки сверяй с исходным рассказом.

## День 23 Фильтрация и уточнение запроса

```sh
npm run rag -- search "Для чего Денис Григорьев отвинчивал гайки в рассказе «Злоумышленник»?"
npm run rag -- ask raw "Для чего Денис Григорьев отвинчивал гайки в рассказе «Злоумышленник»?"
npm run rag -- ask rag "Для чего Денис Григорьев отвинчивал гайки в рассказе «Злоумышленник»?"
```

До фильтра берётся 8 фрагментов, после — не больше 4. `score` — косинусное
сходство векторов, а не вероятность правильного ответа.
Фрагменты ниже 0.3 отсекаются. `rankScore` добавляет небольшой бонус за
совпадение слов: это эвристический реранкинг, без отдельной модели.

`raw` отключает фильтр, переупорядочивание и уточнение вопроса;
проверка цитат остаётся в обоих режимах. На контрольном наборе нужное
произведение найдено в 10 из 10 вопросов с фильтром и без него.
Из 40 выбранных фрагментов к ожидаемым произведениям относятся 36 без
фильтра и 37 с ним. Эффект небольшой — покажи реальные числа.

Теперь вопрос без понятного контекста:

```sh
npm run rag -- rewrite "А кому он всё-таки рассказал?" "Разобрать рассказ Чехова «Тоска»: Иона Потапов и смерть его сына"
```

Покажи `rewritten`: приложение добавило цель задачи.
В проверенном прогоне без уточнения среди первых четырёх результатов
не было «Тоски», после уточнения все четыре результата взяты из неё.
Второй такой пример в отчёте — «Для чего он их отвинчивал?»
с контекстом «Злоумышленника». Уточнение детерминированное:
подставляются сохранённая цель, уточнения, термины и предыдущий вопрос.

Порог можно менять без правки кода:

```sh
RAG_THRESHOLD=0.6 npm run rag -- search "Для чего Денис Григорьев отвинчивал гайки в рассказе «Злоумышленник»?"
```

## День 24 Источники и защита от выдуманных цитат

```sh
npm run rag -- ask rag "Как Ванька подписывает адрес на конверте письма дедушке?"
```

Покажи ответ, `source_url`, раздел и `chunk_id`.
Открой `corpus/chekhov-vanka.md` и найди «На деревню дедушке».
Код проверяет источник, раздел, идентификатор и дословное наличие цитаты
в найденном фрагменте. Один неверный ответ отправляется на исправление;
если проверка снова не проходит, программа отказывается его выдавать.

Для отрицательного примера:

```sh
npm run rag -- ask rag "Как настроить Kubernetes Ingress для двух сервисов?"
```

В проверенном прогоне максимальное сходство около 0.253 — ниже порога 0.3.
Покажи `afterFilter: []`, `abstained: true` и ответ:
«Не знаю по найденным документам. Уточните вопрос или добавьте подходящий
источник». При пустом контексте запрос генерации ответа не выполняется.

В конце покажи режим `filtered` в `report` и 10 ответов в `evaluation.json`:
наличие источников, цитат и оценку смысловой поддержки.
Дословная цитата доказывает её происхождение, но не правильность всех
выводов модели. Ошибку смысла или отказ покажи как ограничение реализации.

## День 25 Чат с историей и памятью задачи

Для новой записи выбери ещё не использованное имя, например `video25`:

```sh
npm run rag -- chat video25
```

Внутри чата введи:

```text
/goal Разобрать рассказ Чехова «Тоска»: Иона Потапов и смерть его сына
/constraint Отвечать коротко и только по рассказу «Тоска»
/clarify Готовим ответ для школьного доклада
/term Иона=Иона Потапов, извозчик из рассказа «Тоска»
/state
Кому Иона Потапов в итоге рассказывает о смерти сына?
А кому он всё-таки рассказал?
/history
/exit
```

Покажи отдельное состояние задачи: цель, ограничение, уточнение и термин.
Каждый новый вопрос запускает новый поиск, ответы сопровождаются цитатами.
Затем снова запусти `npm run rag -- chat video25` и введи `/state`,
`/history`: цель и переписка восстановились из `chat-video25.json`.
Продолжи вопросом «Почему люди не хотели его слушать?» и проверь источники.

История хранится целиком; модели передаются последние 8 сообщений и
отдельное состояние задачи. Память переживает перезапуск, но окно контекста
не бесконечно.

```sh
npm run rag -- scenarios
npm run rag -- report
```

Два сценария по 12 вопросов заданы в `classics-questions.mjs`:
сравнение «Смерти чиновника» и «Хамелеона», сравнение «Шинели» и «Муму».
В `scenarios-report.json` покажи число ходов, ответов с источниками,
сохранение цели и ограничений. Затем прочитай последний ответ каждого
сценария: он должен продолжать исходное сравнение.
Сохранение полей памяти не доказывает соблюдение цели по смыслу.

## Произведения в корпусе

- Чехов: «Смерть чиновника», «Толстый и тонкий», «Хамелеон», «Злоумышленник»,
  «Лошадиная фамилия», «Тоска», «Ванька», «Каштанка», «Размазня», «Пересолил»,
  «Налим», «Хирургия», «Супруга», «Ионыч», «Человек в футляре», «Крыжовник»,
  «О любви», «Попрыгунья».
- Пушкин: «Выстрел», «Метель», «Гробовщик», «Станционный смотритель»,
  «Барышня-крестьянка», «Пиковая дама».
- Гоголь: «Шинель», «Нос», «Записки сумасшедшего», «Коляска».
- Тургенев: «Муму», «Бирюк».
- Толстой: «После бала», «Кавказский пленник».

Ссылки и ревизии записаны в манифесте. Векторы и метаданные хранятся
в `fixed.json` и `structural.json`; кеш — в `embeddings-cache-*.json`.
Для поиска сервер приложения не нужен, но эмбеддинги новых вопросов
и ответы требуют сети.

Старый эксперимент с исходниками остаётся отдельно:
`node examples/ai-advent/rag-cli.mjs index` использует локальные
лексические хеш-векторы и каталог `v3/data/rag/`.
Не путай его с `npm run rag -- index`, который строит нейросетевой
индекс публичной классики.
