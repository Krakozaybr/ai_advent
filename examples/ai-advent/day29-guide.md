# День 29. Оптимизация локальной LLM

Задача — ответы по русской классике с локальным RAG. Сравниваем одну модель
`qwen3:4b` с исходными и изменёнными параметрами и шаблонами запроса.
Профили проверяются последовательно; настройки дней 26–28 не меняются.

## Запуск

Команды запускаются из корня проекта. Нужны Ollama, модели и локальный
индекс дня 28. [Первичная подготовка](local-llm-guide.md).

В первом терминале запусти Ollama и оставь его открытым:

```sh
npm run local:serve
```

Если порт уже занят работающим Ollama, второй экземпляр не нужен.
Во втором терминале запусти сравнение — примерно четыре минуты на компьютере,
на котором выполнен приведённый ниже замер:

```sh
npm run --silent local -- optimize
npm run --silent local -- report 29 --details
```

Проверяются три контрольных вопроса по два раза в каждом профиле.
Для десяти вопросов используй `npm run --silent local -- optimize --all`.
Индекс и векторы вопросов одинаковы. Модель прогревается перед измерениями.
Время включает поиск по готовому вектору, генерацию, проверку цитат,
возможное исправление и опрос памяти, но не подготовку векторов и прогрев.

## Что изменилось

| Параметр | До | После |
| --- | --- | --- |
| temperature | 0 | 0.1 |
| Контекст, токены | 8192 | 6144 |
| Лимит JSON-ответа | 800 | 640 |
| Лимит обычного ответа | 4096 | 1024 |
| Шаблон | Прежний RAG | Ответ на каждую часть вопроса, полные имена и перечисления, подтверждение всех фактов цитатами |

Изменённый шаблон находится в `local-optimization.mjs` (`optimizedPrompt`).
Вопрос и найденные фрагменты не подменяются. Модель должна различать намерение
героя и фактический результат, не добавлять сведения из памяти и признавать,
если части ответа нет в контексте.

Отчёт показывает ошибки, отказы, время, загрузку CPU всего компьютера
и память проверяемой модели по Ollama `/api/ps`. Это не пик RSS процесса;
опрос идёт каждые 500 мс. На Mac GPU использует объединённую память.
Попадание нужного источника не доказывает правильность ответа: нужно отдельно
сверять ответ и цитаты с ожиданием. Мелкие различия времени не доказывают ускорение.

Отчёт и ответы сохраняются в `v3/data/rag/classics-ollama/day29-optimization.json`.
Индексы, веса и отчёты не добавляются в Git.

## Проверенный результат

Замер на macOS, 10 октября 2026: три вопроса, по два повтора в каждом профиле,
в обоих режимах Q4_K_M. Исходный профиль: среднее время 19.04 с,
память загруженной модели 3678 MiB. Изменённый: 19.11 с и 3386 MiB.
Памяти меньше примерно на 8%; ускорения в этом прогоне нет.

В обоих режимах получены ответы без технических ошибок и с нужным источником
во всех шести запросах. При ручной проверке исходный профиль неверно перечислял
карты в «Пиковой даме» и не отвечал явно на вторую часть вопроса. Изменённый
назвал тройку, семёрку, туз и пиковую даму вместо туза. Также проверены полный
адрес Ваньки и цель отвинчивания гаек. Это проверка трёх вопросов, не всей базы;
ответы нового запуска могут отличаться.

## Сценарий видео без озвучки

После проверки покажи сохранённый отчёт:

```sh
npm run --silent local -- report 29
```

Затем отправь одинаковый вопрос до и после оптимизации:

```sh
npm run --silent local -- rag "Какие три карты названы в «Пиковой даме» и что выпадает Германну вместо туза?"
npm run --silent local -- rag-optimized "Какие три карты названы в «Пиковой даме» и что выпадает Германну вместо туза?"
```

Оставь на экране настройки, время, память, ответы и цитаты.
Веб-приложение для CLI-показа не нужно. Для веба запусти в отдельных терминалах
`npm run local:backend` и `npm run local:web`, затем открой
[экран дня 29](http://127.0.0.1:5173/?localDay=29). Выбирай «До» и «После»;
вопросы здесь независимы, без истории предыдущих ответов.

## Отдельное сравнение квантования

Модель `qwen3:4b` уже использует Q4_K_M. Для сравнения с Q8_0:

```sh
npm run local:quantization
npm run --silent local -- optimize --quantization
npm run --silent local -- report 29 --details
```

Этот режим проверяет оба профиля также на Q8_0. Q8_0 в приведённом замере
не проверен: загрузка остановлена из-за низкой скорости. Наличие команды
не означает выполненное сравнение.

Справка: [параметры Ollama](https://docs.ollama.com/modelfile),
[модель Q8_0](https://ollama.com/library/qwen3:4b-q8_0).
