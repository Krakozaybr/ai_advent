# Дни 26–28: локальная модель и RAG

Все команды ниже запускаются из корня проекта. Модель ответов — `qwen3:4b`,
эмбеддингов — `qwen3-embedding:0.6b`. Сначала нужно скачать веса; после этого
локальные запросы не требуют интернета или ключа OpenRouter.

## Подготовка один раз

На macOS с Homebrew:

```sh
brew install ollama
```

Оставь первый терминал работающим:

```sh
npm run local:serve
```

Во втором терминале:

```sh
npm run local:pull
npm run --silent local -- status
npm run --silent local -- index
```

Если корпус ещё не скачан, перед индексацией выполни `npm run rag:download`.
Индексация использует те же 32 произведения и две стратегии разбиения из
дня 21, но пересчитывает векторы локальной моделью. Облачный индекс остаётся
нетронутым. Файлы находятся в `v3/data/rag/classics-ollama/`; веса —
в `v3/data/ollama/models/`. Эти каталоги не коммитятся. Повторная индексация
использует сохранённые векторы неизменённых фрагментов.

Для веб-интерфейса нужны ещё два терминала:

```sh
npm run local:backend
```

```sh
npm run local:web
```

Если backend/frontend уже работают, второй экземпляр запускать не нужно.
Экран локальных дней не запрашивает каталог OpenRouter и не требует ключа.
Обычные ленты доски по-прежнему используют Codex/OpenRouter.

<a id="day-26"></a>

## День 26 — видео без комментариев

```sh
npm run --silent local -- status
npm run --silent local -- ask "Сколько будет 2 + 2? Ответь одним числом."
npm run --silent local -- ask "Объясни в двух предложениях разницу между индексом документов и поиском по нему."
npm run --silent local -- ask "Книг 48. Треть отдали в первую библиотеку, половину оставшихся — во вторую. Сколько осталось? Покажи короткий расчёт."
```

В кадре видны локальный адрес, установленная модель, три вопроса,
фактические ответы, время. Ожидания: 4; индекс создаётся заранее, поиск
выбирает фрагменты для вопроса; 48 − 16 = 32, 32 − 16 = 16.
Для автоматической проверки и сохранения отчёта доступны
`npm run --silent local -- probe` и `npm run --silent local -- report 26`.

<a id="day-27"></a>

## День 27 — веб-приложение

Открой [день 27](http://127.0.0.1:5173/?localDay=27), нажми
«Проверить подключение», отправь вопрос:

> Объясни в двух предложениях разницу между индексом документов и поиском по нему.

Покажи ответ, имя модели, локальный адрес и время. Можно продолжить диалог:

> Приведи короткий пример для библиотеки книг.

Последние пять пар сообщений передаются в следующий запрос. История отдельная
для каждого дня, сохраняется при переключении между локальными вкладками,
но не после перезагрузки страницы. Для доказательства работы без облака
после загрузки страницы и скачивания весов отключи интернет и повтори запрос.
Локальный API не содержит автоматического переключения на облако.

<a id="day-28"></a>

## День 28 — локальный RAG

```sh
npm run --silent local -- rag "Для чего Денис Григорьев отвинчивал гайки в рассказе «Злоумышленник»?"
npm run --silent local -- benchmark
npm run --silent local -- report 28 --details
```

Затем открой [день 28](http://127.0.0.1:5173/?localDay=28), отправь тот же
вопрос. Покажи ответ, дословные цитаты, название произведения и `chunk_id`.
Поиск, эмбеддинг вопроса, генерация и проверка цитат работают локально.
Если модель не выбирает допустимые цитаты, система отказывается отвечать
и просит уточнение. Код проверяет дословность цитат, но не гарантирует,
что каждый вывод модели правильно передаёт их смысл.

Если настроен OpenRouter, сравнение с облаком запускается **отдельно**:

```sh
npm run --silent local -- benchmark --cloud
npm run --silent local -- report 28 --details
```

Только этот явный режим отправляет вопросы и найденные фрагменты в OpenRouter.
Поиск в обоих режимах одинаковый, локальный; меняется модель генерации.
Модель облака задаётся `RAG_ANSWER_MODEL`, по умолчанию `openai/gpt-4.1-mini`.
Ключ читается сервером из `.env` либо прежних настроек в `data/settings.json`.
Новый запуск заменяет предыдущий отчёт сравнения, но не индекс.

Отчёт проверяет три вопроса по два раза для каждой модели:

- Качество: сравни фактический ответ с напечатанным ожиданием и цитатами.
  Попадание нужного произведения само по себе не доказывает правильность.
- Скорость: показано полное время поиска, ответа и возможного исправления
  цитат. Первый вызов может быть медленнее из-за загрузки весов.
- Стабильность: число завершённых запросов, отказов и одинаковых ответов
  в двух повторах. Это небольшая проверка, не нагрузочный тест.

Отчёты лежат рядом с индексом: `day26-probes.json`, `day28-benchmark.json`.
Чтобы сменить локальную модель, предварительно скачай её в Ollama и задай
`OLLAMA_MODEL` при запуске CLI и backend. Облачные имена моделей отвергаются.

Документация: [локальный режим Ollama](https://docs.ollama.com/faq),
[API ответов](https://docs.ollama.com/api/chat),
[API эмбеддингов](https://docs.ollama.com/api/embed).
