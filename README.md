# AI Advent Web

Локальное учебное веб-приложение с пятнадцатью последовательными экспериментами:
от первого запроса к LLM до памяти и контролируемого жизненного цикла задачи.

## Запуск

```bash
npm install
npm run dev
```

После запуска открой <http://127.0.0.1:3000>.

## OpenRouter

Открой «Настройки» в интерфейсе и сохрани API-ключ. Он попадёт в локальный
`data/settings.json`; папка `data` исключена из Git, а сам ключ не возвращается
в браузер. Если в корне уже есть `.env` с `OPENROUTER_API_KEY`, приложение
подхватит его автоматически.

## Текущее состояние

Готовы Дни 1–15:

- День 1 отправляет запрос в OpenRouter и показывает Markdown-ответ;
- День 2 содержит две независимые вкладки: запрос без ограничений и запрос с
  заданным форматом, длиной и stop sequence. У каждой вкладки свой prompt и
  отдельная кнопка запуска;
- День 3 решает одну логическую задачу четырьмя способами: прямо, пошагово,
  через сгенерированный prompt и группой экспертов. После четырёх запусков
  появляется таблица сравнения точности и ресурсов;
- День 4 отправляет один prompt с temperature 0, 0.7 и 1.2. Режимы можно
  запускать отдельно или параллельно, после чего появляется таблица сравнения;
- День 5 сравнивает слабую, среднюю и сильную модели Qwen по проверяемому
  заданию, времени, токенам и фактической стоимости OpenRouter;
- День 6 содержит отдельный серверный класс `LlmAgent` и простой чат. Агент
  формирует сообщения, вызывает OpenRouter и возвращает ответ с метриками.
- День 7 сохраняет один диалог в `data/agent.sqlite`, загружает сообщения после
  перезапуска и отправляет восстановленную историю в каждый следующий запрос.
- День 8 сравнивает короткую, длинную и переполненную историю: до запроса
  оценивает размер контекста, после ответа показывает точные токены OpenRouter,
  а для переполненного сценария включает OpenRouter context-compression.
- День 9 ведёт два параллельных варианта одного диалога. Первый отправляет всю
  историю, второй заменяет старые сообщения отдельным summary и сохраняет
  последние N сообщений дословно. Интерфейс сравнивает ответы и токены.
- День 10 переключает три стратегии одного агента: Sliding Window отбрасывает
  старые сообщения, Sticky Facts автоматически обновляет редактируемый JSON,
  а Branching создаёт две независимые ветки от общего checkpoint.
- День 11 хранит краткосрочную, рабочую и долговременную память в отдельных
  таблицах SQLite. Локальный MCP-сервер предоставляет инструменты памяти через
  `stdio`: агент сам вызывает `memory_save`, а интерфейс показывает слой, ключ,
  значение и причину. Записи можно исправить или удалить вручную.
- День 12 хранит два редактируемых профиля пользователя и параллельно сравнивает
  ответы на один запрос. Оба варианта получают одинаковую память Дня 11.
- День 13 хранит этап, текущий шаг, ожидаемое действие и паузу задачи в SQLite.
  Агент получает снимок состояния вместе с каждым сообщением.
- День 14 хранит инварианты отдельно от диалога и проверяет конфликт до вызова
  модели. Допустимый запрос получает ограничения в системном контексте, а
  конфликтный отклоняется с явным объяснением.
- День 15 задаёт разрешённые переходы и guard-условия для автомата
  planning → execution → validation → done. Интерфейс позволяет намеренно
  проверить запрещённый переход, паузу и восстановление состояния.

По умолчанию используется дешёвая instruct-модель
`qwen/qwen3-30b-a3b-instruct-2507`. Результаты каждого дня можно скачать в JSON.

а не через обычную ленту доски.

[Установка, запуск и сценарий видео](examples/ai-advent/local-llm-guide.md).

OpenRouter и не переключаются на облако при ошибке.

День 29 сравнивает настройки, шаблон и расход памяти локального RAG.
[Запуск и сценарий видео](examples/ai-advent/day29-guide.md).

День 30 — приватный HTTPS-чат на домашнем ноутбуке с ключом доступа и ограничениями.
[Запуск на Windows и проверка с другого компьютера](examples/ai-advent/days-29-30-guide.md#day-30).
