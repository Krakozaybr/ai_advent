# AI Advent v3: основа приложения

Статус: рабочая спецификация. Описывает общую основу для дней челленджа, а не
сценарии каждого дня.

## Цель и границы

Локальное приложение показывает диалоги как вертикальные ленты на общей доске.
Пользователь может вести несколько лент, ответвляться от сообщения и менять
параметры следующего запроса. Учебные дни используют общую историю, генерацию
и инструменты агента; их код не должен дублировать эти механизмы.

Версия v2 остаётся работоспособной и не переносится в v3 автоматически. Новый
код размещается отдельно в `v3/`.

## Устройство проекта

- `v3/backend/` — один локальный Ktor-сервер, разделённый на модули досок,
  истории, генерации, провайдеров и позднее инструментов. Правила изменения
  истории и сохранение данных живут здесь.
- `v3/frontend/` — React + TypeScript + Vite. Фронт отображает доску, принимает
  ввод, управляет камерой и выделением. Он не хранит вторую независимую копию
  истории и не обращается к провайдерам моделей напрямую.
- Фронт отправляет команды по HTTP и получает изменения генерации потоком
  событий. Сервер остаётся источником окончательного состояния.

Микросервисы не нужны: приложение запускается локально для одного пользователя.
MCP-серверы и Codex app-server могут быть отдельными процессами, но это
подключаемые инструменты, а не самостоятельные части домена доски.

## Данные доски

Каждая доска — отдельный файл SQLite в локальном каталоге, исключённом из Git.
Файл содержит версию схемы, ленты, сообщения, связи ветвей, настройки и запуски
генерации. Ключи API и другие секреты хранятся отдельно и не попадают в файл
доски или ответы HTTP API.

- **Лента** содержит упорядоченную историю, ширину, положение и настройки по
  умолчанию: провайдер, модель, доступные навыки и MCP-подключения.
- **Сообщение** имеет устойчивый идентификатор, роль и содержимое. На первом
  этапе нужны сообщения пользователя и публичные ответы модели; скрытые
  рассуждения не сохраняются и не показываются как текст модели.
- **Запуск** хранит ленту, снимок параметров запроса, состояние
  `running/completed/failed/cancelled`, итоговый ответ и доступные метрики.
  Изменение настроек ленты не меняет уже запущенный запрос. Параметры можно
  переопределить для конкретного запуска.

На одной ленте одновременно выполняется не более одного запроса: иначе порядок
сообщений неоднозначен. Разные ленты могут генерировать ответы параллельно.
Переключение доски или перезагрузка страницы не отменяет серверный запуск.

## История и ветвление

- Ветка от сообщения получает снимок истории родительской ленты до этого
  сообщения включительно и затем развивается независимо.
- Клон ленты получает снимок всей её истории и настроек.
- Изменение или удаление сообщения отсекает все более поздние сообщения
  **только в этой ленте**. Уже созданные ветки и клоны не меняются.
- Копирование сообщения в другую ленту создаёт новое сообщение с новым
  идентификатором; исходное остаётся на месте.
- Если точка ответвления исчезла из текущей версии родительской ленты, данные
  дочерней ветки сохраняются. Интерфейс должен обозначить историческую связь.

## Подключение моделей

Общий контракт провайдера охватывает запуск, поток публичных событий,
завершение, ошибку и отмену. Поддерживаемые настройки и операции провайдер
объявляет отдельно: OpenRouter и Codex не обязаны иметь одинаковые возможности.

Codex подключается через локальный app-server с входом по подписке ChatGPT,
без ключа OpenAI API. Сервер приложения получает список моделей, создаёт или
возобновляет сессию и переводит публичные фрагменты ответа в общий поток
событий. Температура и параметры Chat Completions для Codex не передаются.
Связь ленты с сессией Codex хранится как локальная привязка. Сам файл доски
переносим как история и настройки, но перенос живой сессии Codex на другую
машину не обещается. Запросы на выполнение команд, изменение файлов и другие
подтверждения не принимаются автоматически. Ориентир —
[официальный протокол Codex app-server](https://learn.chatgpt.com/docs/app-server).

OpenRouter получает историю из файла доски и использует ключ в серверном файле
с правами только владельца. Оба провайдера сохраняют снимок параметров каждого
запуска; провайдер ленты задаётся при создании и наследуется ветками и клонами.

## Контракт потока

Каждое событие содержит `boardId`, `laneId`, `runId`, порядковый номер, тип и
данные. Минимальные типы: `run.started`, `text.delta`, `run.completed`,
`run.failed`, `run.cancelled`. После обрыва соединения фронт запрашивает
сохранённое состояние доски; частичный текст не выдаётся за завершённый ответ.

Сервер проверяет операции над историей до обращения к модели. Ошибки провайдера
сохраняются у соответствующего запуска и видны в интерфейсе без утечки ключей.

## Первый реализуемый срез

Одна доска и одна лента: создать доску, проверить вход в Codex через подписку
ChatGPT, отправить сообщение через локальный app-server, увидеть ответ по мере
поступления, закрыть страницу и открыть сохранённый диалог. Это проверяет
границы фронта и сервера, файл доски, привязку к сессии Codex и поток событий,
не требуя сразу всей графической доски.

Критерии готовности первого среза:

1. После перезапуска сервера сообщения и настройки ленты восстанавливаются;
   продолжение диалога использует прежнюю сессию Codex, если она доступна.
2. Ответ виден постепенно; после завершения он совпадает с сохранённым.
3. Ошибка запроса остаётся привязана к запуску и не превращается в ответ модели.
4. Вход выполняется через Codex/ChatGPT; приложение не просит ключ OpenAI API и
   не копирует токены Codex в файл доски, браузер или Git.
5. Есть автоматические проверки с подменённым app-server и ручной проход
   сценария с реальным Codex в браузере.

После первого среза отдельно добавляются ветки, редактирование истории,
параллельные ленты и адаптер OpenRouter. Их сроки оцениваются по фактическому
времени первого среза, а не по числу оставшихся дней.
