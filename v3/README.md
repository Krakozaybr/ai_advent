# AI Advent v3 — первый срез

Универсальное локальное рабочее пространство: Ktor хранит каждую доску в отдельном
SQLite-файле, а React-интерфейс получает изменения запросов через SSE. Исходный
`v3/data/board.sqlite` остаётся первой доской; новые файлы создаются в
`v3/data/boards/`. v2 продолжает запускаться из корня.

## Запуск

В первом терминале:

```sh
cd v3/backend
./gradlew run
```

Во втором:

```sh
cd v3/frontend
npm install
npm run dev
```

Открой `http://127.0.0.1:5173`. Backend использует установленный `codex` из
`PATH` и вход через ChatGPT для лент Codex. Для лент OpenRouter сохрани ключ в
меню «Ключ OpenRouter»; он остаётся в серверном файле и не передаётся браузеру.
Провайдер выбирается при создании ленты, ветка и клон наследуют его.

Для OpenRouter можно разрешить MCP-инструменты в настройках ленты. Backend
читает список серверов только из `v3/data/mcp-servers.json`; начальный пример
находится в `v3/mcp-servers.example.json`. Скопируй его в `v3/data/` и оставь
в реестре только доверенные команды. Доска хранит только выбранные server ID и
имена tools. Каталог показывает подключение и JSON Schema. Инструменты сейчас
доступны только OpenRouter; для Codex UI показывает ограничение явно. Пример
`local-catalog` находится в `examples/mcp/` и работает без сети и ключей.

Платформенные tools `lane-history` и `board-memory` доступны OpenRouter-лентам
без регистрации пользовательской команды. Первый ищет в сохранённом transcript
своей ленты, в том числе за пределами `sliding_window`. Второй использует
отдельную `v3/data/memory.sqlite`: рабочие памяти выбираются по имени, а
longTerm общий для доски. UI показывает память и approval на доске; инструменты
выбираются отдельно для каждой ленты. Вызов может дать модели дополнительные
данные, но не гарантирует более качественный ответ. `v3/data/` исключён из Git.

Задачи доступны как общая возможность платформы: UI и REST API работают с
задачами выбранной доски, а зарегистрированный `board-tasks` MCP-сервер даёт
OpenRouter-ленте инструменты чтения и предложения изменений. Данные хранятся в
отдельной `v3/data/tasks.sqlite`; MCP scope доски сервер получает из доверенной
базы и ID ленты. Создание и изменения MCP проходят через обычный approval flow
ленты; autoapprove остаётся выключен по умолчанию. Этапы задачи — `planning`,
`execution`, `validation`, `done`: SQLite разрешает переход только на следующий
этап, требует утверждённый непустой план до `execution` и запрещает завершение
до `validation`. Шаг, ожидаемое действие, пауза и комментарии сохраняются и
восстанавливаются после перезапуска. UI показывает причину отклонённого перехода.

## Проверки

```sh
cd v3/backend && ./gradlew test
cd v3/frontend && npm test && npm run build
cd ../.. && npm test && npm run build && git diff --check
```

Проверки Codex используют подменённый app-server gateway, а OpenRouter —
подменённый HTTP-транспорт. Для ручного прохода открой несколько досок и лент,
отправь запросы через оба провайдера и проверь отмену и восстановление истории
после перезагрузки. Выбор доски сохраняется в браузере.
